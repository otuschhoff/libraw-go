# M1: bounded RAW decoding

This is the historical Phase 5 snapshot. Phase 6 subsequently adds an independent
renderer and owner-approved, provenance-labelled white/color profiles; see the
[current rendering contract](rendering.md). The M1 sensor-code, ownership and
fixture-parity contracts remain unchanged.

M1 is the raw-decoding milestone, not a full LibRaw replacement, RGB developer,
or claim of universal Olympus/OM System camera support. The production module
uses only the Go standard library, requires Go 1.26 or newer, and builds with
`CGO_ENABLED=0`. Native reference tools are development-only.

No release tag or binary distribution is created by this milestone commit.
The API is still an early, layout-scoped implementation. Rendering, verified
camera color profiles and usable RGB/PNG output remain Phases 6-7.

an implemented operation within limits; it does not prevalidate unread pixels.

## RAW data and calibration contract

- `Pixels` contains caller-owned 12-bit sensor codes in `uint16`, not codes
  scaled to fill uint16 and not pixels from an embedded JPEG.
- `Stride == Width`; `len(Pixels) == Width*Height`. The entire stored plane is
  returned without crop, rotation, black subtraction, WB or other processing.
- CFA and calibration are anchored to the unrotated sensor origin, with
  separate green positions. EXIF orientation is retained as metadata.
- A verified active crop is a half-open rectangle, not an applied transform.
  An unavailable crop is empty and has an explicit diagnostic.
- Black/WB metadata preserves provenance. Missing white level, camera-to-XYZ
  transforms and firmware are not guessed from reference camera tables.
- RAW results and previews have caller-owned buffers and must be closed, as
  must File. Metadata diagnostics are borrowed read-only; Clone makes an
  unbudgeted caller-owned snapshot. File borrows its immutable ReaderAt; the
  caller keeps it open and unchanged while operations are in progress.
- Concurrent calls require a concurrently readable input. `os.File.ReadAt`
  and `bytes.Reader.ReadAt` satisfy that requirement. Limits are per operation;
  an inherited/shared Budget also bounds aggregate reservations. See
  [in-process safety](in-process-safety.md) for the current lifetime contract.

See the [algorithm and geometry evidence](orf-layouts.md) for precise layout,
prefix, predictor, CFA, numeric-domain and crop rules.

## API usage

```go
package example

import (
    "context"
    "os"

    libraw "github.com/otuschhoff/libraw-go"
)

func DecodeFile(ctx context.Context, path string) (*libraw.RawImage, error) {
    input, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer input.Close()
    info, err := input.Stat()
    if err != nil {
        return nil, err
    }
    file, err := libraw.Open(ctx, input, info.Size(), libraw.OpenOptions{})
    if err != nil {
        return nil, err
    }
    defer file.Close()
    return file.DecodeRaw(ctx) // The caller must Close the successful RAW result.
}
```

The returned plane remains valid after the input closes. For an in-memory
input, pass `bytes.NewReader(data)` and `int64(len(data))` to the same `Open`.
Use `Metadata()` independently of RAW support; use `Preview(ctx)` to obtain
original embedded JPEG bytes, never as a RAW fallback. `orfinfo` prints
deterministic metadata/capability JSON without decoding the sensor plane:

```sh
CGO_ENABLED=0 go run ./cmd/orfinfo /path/to/photo.orf
```

`Capabilities()` can explain why a control is unavailable without decoding;
`DecodeRaw` itself preserves typed `ErrUnsupported` versus `ErrLimitExceeded`
outcomes for programmatic error handling.

## Limits, cancellation and errors

Default per-operation limits are 1 GiB input, 100 million pixels, 32768 pixels
per dimension, 128 IFDs, depth 16, 4096 entries per IFD, 16 MiB metadata, 64 MiB
preview and 1 GiB accounted working buffers. Zero selects the default; negative
or contradictory limits are invalid. Larger positive limits do not disable
checked arithmetic, platform-sized allocation checks or validated file extents.

RAW working storage is one output plane plus one input row for word decoding
or a 4096-byte buffer for predictive decoding, plus diagnostic storage. It is
not a whole-file buffer or a second image. Buffer quotas do not promise a Go
runtime RSS/GC limit. Preview extraction has its own byte/header-working checks.

Cancellation is polled between RAW rows, before RAW success, and between preview
chunks. A blocked caller-supplied `ReaderAt` cannot be interrupted. Errors never
return a partial `File`, `RawImage` or `Preview`. Predictive reads do not extend
past the declared strip or zero-fill required fields; unused final bits and
declared opaque trailing bytes are not speculative lookahead.

Use `errors.Is` for classification and retained causes; use `errors.As` with
`*libraw.Error` for operation, layout and available byte/bit/tag/IFD context:

| Error | Meaning |
|---|---|
| `ErrNotORF` | Input does not have recognized ORF framing |
| `ErrUnsupported` | Recognized but unevidenced signature/layout/mode/encoding |
| `ErrCorrupt` | Contradictory structure, invalid fields or out-of-domain samples |
| `ErrTruncated` | Declared extent or required input bits/bytes are missing |
| `ErrLimitExceeded` | Resolved resource or platform-sized allocation bound exceeded |
| `ErrInvalidOptions` | Invalid limits, nil input/context, or unopened `File` operation |
| `ErrNoPreview` | No valid supported preview within the configured limits |
| `ErrCalibrationUnavailable` | Reserved contract for development; M1 does not render |

A short read can preserve both `ErrTruncated` and its underlying I/O error;
classifications are not necessarily mutually exclusive. Real I/O failures,
even joined with EOF on a full read, remain failures. Cancellation preserves
`context.Canceled` or `context.DeadlineExceeded`.

## Reproducible validation

Ordinary tests never download files or invoke LibRaw/ExifTool. Acquire the
licensed originals explicitly through the [reference workflow](../tools/reference/README.md):

```sh
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go run tools/reference/main.go fetch
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go run tools/reference/main.go verify
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go test -tags=integration -count=1 ./...
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go vet ./...
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go build ./...
GOTOOLCHAIN=go1.26.0 go test -race -tags=integration -count=1 ./...
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go test tools/reference/main.go tools/reference/main_test.go
```

Missing/changed required fixtures, golden hashes, gzip checksums, geometry or
samples fail; they never silently skip. `ORF_FIXTURE_DIR` optionally selects an
existing licensed fixture directory. Golden generation/reproduction remains
pinned and separate; production decoder output never regenerates the oracle.
The reference tool's archive unit tests need a writable ignored reference cache.
Race instrumentation requires the platform C toolchain, not a production Cgo
dependency.

The six fuzz gates below each require at least ten minutes without failure.
These commands are independent and may run separately; ordinary/fuzz tests do
not need the photographs or network. `-parallel=1` limits each fuzz run's workers:

```sh
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go test -run='^$' -fuzz='^FuzzOpenORF$' -fuzztime=600s -fuzzminimizetime=1s -parallel=1 .
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go test -run='^$' -fuzz='^FuzzMakerNotes$' -fuzztime=600s -fuzzminimizetime=1s -parallel=1 .
```

[CI](../.github/workflows/ci.yml) tests Linux/macOS on amd64/arm64 with Go 1.26.0,
plus Linux/amd64 on Go 1.27.3. All five jobs explicitly acquire/hash-check
fixtures, run integration tests, vet, build, reference-tool tests and races.
The Linux/amd64 minimum-Go job also **executes** the full 32-bit suite, including

publishing an M1 tag. Broader OS/CPU versions are not certified by these runners.

## Performance and release boundary

Benchmarks use the fixed input hashes/dimensions in the manifest and print
Go/OS/CPU information. Parse and decode are separate:

```sh
GOTOOLCHAIN=go1.26.0 CGO_ENABLED=0 go test -tags=integration -run='^$' -bench='BenchmarkReference(Open|Decode)$' -benchmem -benchtime=300ms -count=3 .
```

Parse benchmarks use a warmed file-backed `ReaderAt`; they do not count the
entire input file as bytes processed. Decode reports elapsed time, bytes/op,
allocations/op and megapixels/second. Measure without simultaneous fuzz/race
load. More than 10% timing regression on the same environment needs repeated
investigation, not a noisy cross-runner hard timing gate. Allocation tests
ensure counts do not grow with row/sample count, and exact quota tests enforce
accounted buffer bounds before I/O/allocation.

Three 300-ms repeats on Apple M1 Max, macOS/arm64, Go 1.26.0, `CGO_ENABLED=0`,
without concurrent fuzz/race work recorded:

|---|---:|---:|---:|---:|---:|---:|---:|
| E-1, 2624 x 1966 | 61.0-64.5 us | 90,421 | 529 | 7.70-7.89 ms | 654-670 | 10,328,074-10,328,325 | 4 |
| E-400, 3768 x 2840 | 67.7-69.8 us | 105,365-105,366 | 557 | 16.3-17.5 ms | 611-657 | 21,414,656-21,414,686 | 4 |
| E-410, 3720 x 2800 | 53.1-54.8 us | 86,315-86,316 | 524 | 385-389 ms | 26.75-27.04 | 20,836,864-20,836,880 | 4-5 |
| E-510, 3720 x 2800 | 54.5-54.7 us | 86,315-86,317 | 525 | 404-407 ms | 25.62-25.79 | 20,836,864 | 4 |

Predictive iterations exceed 300 ms, so each such repeat measures one decode.
The occasional additional 16 bytes/one allocation also appears on the unchanged
Phase 4 baseline; fixed allocation-count tests remain row-independent. The
production decoder code is unchanged in Phase 5; no extra full-image/strip
buffer was found or introduced.

Initial E-400 timings exceeded the older Phase 4 measurements by more than 10%,
so both the committed Phase 4 revision and current code were measured again,
five repeats each in this session. E-400 median was 15.55 ms at baseline versus
16.37 ms current (+5.3%); E-410 was 387.4 versus 394.1 ms (+1.7%). Individual
current repeats varied from 15.57-17.86 ms and 383.5-458.1 ms respectively.
This investigation does not establish a sustained median regression above 10%;
the ranges and one-iteration allocation noise are retained, not hidden behind
a brittle timing assertion. These observations are not portable performance
promises. Future comparisons must use the same hashes/toolchain/environment.

Newer parameterized 12/14-bit codecs, other ORF signatures, compressed
multi-strip restart schemes, alternative packing, high-resolution/pixel-shift,
ORI and multi-frame modes remain unsupported. Missing calibration is retained
explicitly and does not prevent unprocessed RAW extraction. RGB rendering and
the combined M1+M2 definition of done are not claimed here.
